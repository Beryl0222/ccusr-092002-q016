# 医保适配器适配认证服务

国家医保医疗服务项目目录跨省启用前，各医院的收费、医嘱、病案系统对同一国家项目可能给出不同的省级代码组合。本服务在隔离的认证环境中判定医院适配器的**兼容性**，避免接口差异被带入跨省结算。

> 边界：本服务只处理**合成测试用例**与兼容性结论，不接触、不转发、不出具任何真实患者账单。

## 认证模型

```
目录版本(catalog_mapping.json)
   │  国家项目 + 省级映射(direct/one_to_many/conditional) + 生效区间 + 撤销 + 互斥组
   ▼
不可变测试包(按 目录版本×省份 密封, 机构签名)
   │  逐机构水印分发（泄露溯源）
   ▼
医院登记软件版本/转换规则/隔离环境指纹 → 隔离环境执行 → 逐例输出 + 日志指纹 + 签名声明
   ▼
兼容性判定（阻断项一票否决）→ 证书 / 不予发证
```

### 关键规则

- **不可变测试包**：包体含 `cases_hash`、封皮含 `package_hash` 并由经办机构 Ed25519 签名；篡改用例或封皮即校验失败。同一（目录版本, 省份）重复发布返回原包与原哈希（跨重启一致）。
- **五类关键用例**：一对多组合、互斥项目、生效边界（生效首日/前一日、失效末日/次日）、撤销（撤销日后拒付）、历史就诊日期（撤销前区间内仍按当时映射）。所有用例均为关键用例。
- **阻断发证的情形**：
  - `critical_case_failure`：任一关键用例输出与期望不一致（代码集合、接受标志或拒绝原因）；
  - `environment_changed`：提交的环境指纹与登记的隔离环境指纹不符；
  - `test_package_leaked` / `package_leaked`：该机构水印副本或整包已被报告泄露；
  - `invalid_signature` / `invalid_declaration_claim`：医院签名声明缺失、伪造或与提交内容/包哈希/日志指纹不一致。
- **幂等**：同一软件构建对同一测试包的首个结论即最终结论；任何重复上传都原样返回首次结果。整改后须重新登记构建（新版本号/环境指纹）再进入新一轮认证。
- **人工豁免**：必须同时限定**机构、软件版本与转换规则版本、有效期限、整改计划**，并指明被豁免的关键用例；四项缺一或期限已过不予登记。豁免仅在期限内对精确匹配的机构+版本+用例生效，发证状态为 `conditional`，例外意见全文进入证书。
- **目录修订与复测**：修订只把**受影响**适配器（按登记省份与国家代码交集）标记为需复测；未受影响的适配器不重测，旧证书不失效，其覆盖范围声明继续说明“当时的目录版本、省份与测试包”。
- **灰度门槛**：灰度期仅累计**匿名**聚合计数（暴露数、差异数、按国家代码分桶），不记录机构/构建标识。样本量 ≥ 100 且差异率 ≤ 1% 才允许扩大使用。
- **可复原性**：审查者凭一张证书可复原测试包全文、目录版本快照、医院构建登记、豁免意见与整改计划、双方签署者，并就地复核机构签名、包签名、包完整性与目录哈希。
- **租户隔离**：医院只能读取本机构的分发副本与证书，无法看到其他机构的实现与输出；审查复原接口仅审查者可用。

## 角色与 API

Bearer 令牌（`Authorization: Bearer <token>`）。

| 角色 | 端点 | 说明 |
| --- | --- | --- |
| 经办机构 | `POST /v1/hospitals` | 登记医院（名称、覆盖省份、签名公钥） |
| 经办机构 | `POST /v1/reviewers` | 创建审查者账户 |
| 经办机构 | `POST /v1/packages` | 按目录版本+省份发布不可变测试包（重复发布返回原包） |
| 经办机构 | `POST /v1/leaks` | 报告整包泄露或某机构水印副本泄露 |
| 经办机构 | `POST /v1/revisions` | 应用目录修订，圈定需复测适配器 |
| 经办机构 | `GET  /v1/grayscale/decision` | 读取匿名差异统计与扩大使用决定 |
| 医院 | `POST /v1/builds` | 登记软件名称、软件版本、转换规则版本、隔离环境指纹 |
| 医院 | `POST /v1/packages/:id/distribute` | 领取带机构水印的测试包副本 |
| 医院 | `POST /v1/submissions` | 提交逐例输出、日志指纹与签名声明（幂等） |
| 医院 | `GET  /v1/certificates/:id` | 读取本机构证书 |
| 医院 | `POST /v1/grayscale/events` | 上报灰度比对事件（仅匿名计数落库） |
| 审查者 | `POST /v1/waivers` | 批准人工豁免（四要素） |
| 审查者 | `GET  /v1/review/certificates/:id` | 证书全要素复原与验签 |

提交声明（医院私钥签名）须覆盖：`org_id`、`registration_id`、`package_id`、`package_hash`、
`software_version`、`rule_set_version`、`env_fingerprint`、`log_fingerprint`、`results_hash`、`submitted_at`。

## 目录文件

`contracts/catalog_mapping.json`：

- 保留 `service` 与公开 `sample`（无真实个人资料、凭据或生产连接信息）；
- `catalog_versions` 为版本化时态目录，当前含 `2026.1` 与 `2026.2` 两个版本，
  覆盖直接映射、一对多（外科组合）、条件分支（检验/住院门诊）、护理等级互斥组、撤销项目及闽/浙两省，
  用于测试包生成、修订差异与按省份复测判定。

## 运行

```bash
npm run check          # 服务身份自检
npm test               # 33 项契约/领域/HTTP 测试
npm start -- --port 8000 --data data/state.json --key-file data/authority.pem
```

机构签名密钥首次启动自动生成并以 `0600` 权限持久化；状态 JSON 在每次写操作后落盘，
重启后旧测试包哈希与旧证书签名仍可验证。

## 代码结构

```
src/domain/crypto.js         稳定序列化、SHA-256、Ed25519 签名/验签
src/domain/time.js           日期边界与有效期工具

src/domain/testpackage.js    五类用例生成、密封、完整性校验、水印副本
src/domain/certification.js  登记/分发/判定/豁免/泄露/复测/灰度/审查复原
src/domain/store.js          JSON 持久化（测试用内存模式）
src/app.js                   HTTP 路由与角色鉴权
src/service.js               装配与启动入口
test/                        目录、测试包、认证、审查、复测、灰度、HTTP 端到端
```
